# Public reader
- Read root AGENTS.md. Publish static reader pages only; never ship editor credentials, draft/trash documents, or draft-only media.
- Preserve stable individual entry URLs, archive, RSS, sitemap, and configured project-path/custom-domain links.
- `notifications.json` uses the existing published-post helpers and exposes only version, build revision, and public IDs/raw titles (possibly `""`)/canonical URLs/publication dates. Archive, permalink, RSS and navigation labels use shared `entryLabel`; where a date already sits beside the title, a blank-titled entry shows that date once as the link. Its commit must match `revision.json`; never emit bodies, media metadata, or draft/trash IDs.
- Home starts closed; opening selects latest, while stable entry URLs open directly. Entries order oldest to newest with ID tie-break, flattening every page consecutively. Page controls select logical faces, entry controls jump to first faces, and selection within a visible spread does not fake a turn. History remains entry-based. Notebook pages never use width-based reflow; accessibility reading mode reflows complete content.
- Preserve semantic fallback HTML with JS disabled and `?reading=1`, printing, archive/RSS/sitemap and existing permalinks. Only visible faces enter accessibility navigation; animated copies remain inert.
- `scripts/verify-notebook.mjs` measures every page of published v2/v3 entries using production CSS/fonts before Astro output. Failure must stop the candidate build. No measurement files or draft media may enter `dist-blog`.
- Run `npm run build:blog`. For output/privacy regression run `node tests/blog-build.mjs`, then `node tests/public-browser.mjs`; afterward rebuild actual repository content to remove fixture output.
- GitHub Actions deploys this component; a Worker deploy does not update the public blog. Never replace the public reader with the legacy docs editor build.
- `prototypes/diary.html` is a local-only five-entry demonstration. It must remain outside production content/output and must never be deployed as repository posts.
- Music lists are optional published entry metadata, passed through the same published-only book data and shown in accessible/no-JS reading. Never emit draft/trash music. Spotify images use the approved remote hosts without cropping/pixelation/overlays; attribution is an unmodified official asset with separate license metadata.
- Update this file for navigation, output, or deployment contract changes.
- Full-list entry position supplies per-entry palette to book and permalink/reading fallback. Excerpts/covers traverse all pages, including PNG covers; RSS/sitemap/notifications still contain one record per entry. Media copying fully decodes published references sequentially and excludes draft/trash assets. Git PNGs additionally pass the shared full `cleanPng` decode with byte-identical output, because the Worker stores them after structural checks only.
- Published R2 references are copied byte-for-byte only after SHA-256/key, MIME, static decode, metadata and provisional bound checks. `published-media.json` lists the sorted validated R2 subset beside the matching `revision.json`; local reader compatibility does not authorize provider credentials or deployment.

# Studio changes
- Read root AGENTS.md. Authoring is text/photos only: preserve Write and Move & resize separation, finger scrolling, text selection and undo/redo. Draw/pen/stamp creation is retired; preserve legacy drawings, strokes and groups through rendering, recovery, import/export and saves.
- IndexedDB is recovery, not cross-device storage or a backup. Failed uploads, expired login, and conflicts must retain local content and staged receipts.
- Save draft never publishes; Save on a published entry requests an update. Track deployment by entry and exact revision, including after reopening.
- Keep user text as structured rich text; sanitize supported pasted content and validate imports before mutation. Preserve existing entries on import.
- Check affected interactions with `tests/browser.mjs`, `tests/drawing.mjs`, `tests/cloud-browser.mjs`, or `tests/reliability-browser.mjs` against local Vite. Test with substantial text/photos/ink when changing layout or input.
- Existing tooth stamps remain ordinary legacy drawing objects; do not expose new stamp creation. Page color is a wordless page-shaped popover of named accessible swatches, shared with preview; the browser preference is not published entry metadata.
- `music-editor.js` edits per-entry Artists/Songs metadata in a native dialog. Save lists uses one existing undo checkpoint and recovery mutation; preview requests must not overwrite a changed/closed form. Pasting a full matching Spotify link automatically fetches its title/artwork; retain retry and manual names if lookup fails. New lists have three slots; retain editable older extra rows, while only the first three are displayed. Ignore stale responses after link/title edits, removal, closing or changing entries. Backup/import and online saving carry the same metadata; no demo defaults in new entries.
- Update this file when interaction or persistence contracts change.
- New entries use v2 notebook geometry. Draft overflow remains editable on a visible mat and exportable; publication/live revision updates require rendered fit. Old entry formats are unsupported; retain unknown recovery payloads unchanged for export.
- Production text styles and title/date placement must match the shared notebook renderer. Studio pointer conversion subtracts the page furniture offset before storing composition coordinates. Mode changes use Tiptap `setEditable(..., false)` to avoid artificial content/undo updates.
- Public preview loads the shared book renderer on demand for the active unsaved entry. Returning disposes its effects and retains studio selection/content. Unsupported recovered archives remain untouched in IndexedDB and export as their original payload.
- Unsupported recovery blocks automatic persistence until the user selects the explicitly labeled discard/start-fresh action. That action creates a blank v2 archive and resets undo; never overwrite unread recovery on hydration.
- Load interact.js on first Arrange use; mount its listeners only after loading, and respect the latest mode intent if input arrives during loading. Keep initial studio assets within the budget without weakening recovery or required writing functionality.
- Keep viewport keyboard adjustments outside canonical document coordinates. The keyboard save rail uses the existing save/update action and current cloud/recovery state. Preview preserves editor selection/scroll; its external links open separately, and preview keyboard shortcuts must not change studio undo/selection.
- Studio layout uses available width: Entries rail at ≥1000px, native drawer below; Properties is explicitly opened, rail at ≥1280px, native modal below. Reconcile width changes without stale modal state or lost input focus. Native menu controls retain one stable ID each; capacity fixtures are development-only.
- Title readiness/touched state is view-only per entry. Publication/update awaits fresh canonical fit and exposes an actionable issue; draft save/export remain available. Empty prompts and green/wood furniture stay outside canonical content. Scope authoring styles to studio surfaces, excluding the mounted public preview.
- Presentation changes retain Tiptap instances, selection, serialized content and undo. Ignore hidden text nodes in size observation; object selection alone creates no checkpoint/save. Arrange targets use inverse scale for ≥44 screen pixels. Measure the header for preview bounds, and restore surviving inputs/editors and scroll on return or lazy-load failure.

- New text defaults to Caveat handwriting 32px with fixedHeight:true; eight edge/corner handles reshape text in rotated local coordinates, with independent width/height. Legacy text retains auto-height until explicit reshape. Fixed boxes automatically fit rich text inside their dimensions, regrowing only to the preferred maximum size. shared/text-fit.js owns derived fitting for editor and reader; never persist its fitted size or expand the box on typing. Refit when fonts load and expose small/unfittable-text feedback; the height-expanding Fit text action is retired. Photos retain aspect ratio and have an external rotation handle with degree snapping/reset and keyboard/numeric alternatives. Selection exposes Delete outside Properties; every gesture has one undo checkpoint and cancellation restores all metadata. The retired drawing regression now checks legacy ink preservation instead of pen creation.
- Local photo data URLs must be decoded into a Blob before createImageBitmap; do not fetch(dataUrl), because img-src data: does not authorize it under connect-src. Keep the deployed CSP narrow. tests/cloud-csp.mjs serves the production editor with public/_headers and mocked APIs; build the editor before running it to cover actual upload/save under CSP.

# Saving service and authorization
- Read root AGENTS.md. All studio assets are gated server-side; logged-out users receive a sign-in page.
- Only current write access to the configured repository grants studio access. Recheck permissions for existing sessions; read-only/removed collaborators must be rejected. Never authorize by login text or client claims.
- Preserve OAuth state/PKCE, secure HttpOnly same-origin cookies, encrypted expiring KV sessions, origin/CSRF checks, upload validation, and rate limiting.
- Repository writes use checked commit snapshots, exact base revisions, atomic document/assets commits, and non-forced ref updates. Stale saves cannot resurrect trash.
- Trash preserves content; restore returns a draft; publication/removal waits for a successful public build. Keep API status truthful.
- Run `npm run test:server`. Live checks must not publish test content. Changes to authorization/permissions require explicit authorization before deployment.
- While `PRIVATE_VERIFICATION` is `true`, allow ordinary draft saves but reject publish/unpublish and any mutation of published entries. The verification build may include the in-memory diary demo behind the same studio authentication gate; normal editor/public builds exclude it. Disable this flag only with authorization for public publishing.
- Update this file and SETUP.md when access, secrets, bindings, endpoints, or lifecycle contracts change.
- Accept and clean fixed-page v2 and nested-page v3 contracts; reject old or unknown formats. Validate every page with entry-wide resource/ID/group limits. Draft saves may overflow. Titles may be blank, and whitespace-only titles are cleaned to `""`. Before committing publication or a published revision update, reject obvious rotated/object/ink bounds violations. Commit messages use the shared `entryLabel`. Canonical text/title fit is additionally enforced by the static build; preserve revision-based failure reporting.
- GET `/api/spotify` requires current repository write authorization and rate limiting. Validate artist/track URLs before fetching the fixed Spotify oEmbed endpoint; reject redirects, use a seven-second timeout and 32KB body bound, ignore embed HTML. Return 400 for invalid links and 502 for provider failures. Keep artwork hosts restricted by shared validation and both Worker/static studio CSPs; preserve manual editing on failure.
- Session capabilities advertise readVersions [2,3], writeVersion 3 and SCRAPBOOK_WRITES_ENABLED. Default false permits legacy v2/JPEG operations but rejects v3/PNG and lifecycle mutations of existing v3. Enabled requires X-Studio-Contract:3 before mutation; never replace existing v3 with v2. Header compatibility does not grant authorization.
- PNG uploads use shared/png.js structural-only validation (`inflate:false, crc:false`): static RGBA8 header, bounds, chunk lengths/order, contiguous IDAT, no APNG/unknown critical chunks or trailing bytes. Retain alpha and strip ancillary metadata. CRC/inflate/filter checks run in the publish build; never let Worker-accepted bytes become public without them. Keep the PNG upload CPU path lean: native framed body read, zero-copy, string-built base64 body. `/api/posts` returns approximate `storageBytes` from the existing tree snapshot. JPEG limits are separate. `parseMediaPath` distinguishes Git blob SHA references from R2 SHA-256 keys. Git paths/receipts still commit atomically; R2 saves fail closed while writes are disabled. Authenticated R2 hydration requires current repository write access and an optional private `MEDIA_BUCKET` binding. Run desktop-media tests and real local workerd profile after validator/limit changes; Node timing cannot establish Free runtime suitability.
